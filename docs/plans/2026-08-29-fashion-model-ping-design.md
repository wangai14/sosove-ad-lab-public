# 商品提示词面板：模型连接测试设计

## 目标

在现有模型配置区增加一次可见、可解释的模型试调用。测试必须验证当前 Base URL、API Key 和模型 ID 能真正完成一次 OpenAI-compatible `chat/completions` 请求，而不只验证端口或 `/models` 是否可访问。

## 方案

- 复用服务端现有 `POST /api/config/test/ai`，发送 `testMode: "invoke"`。
- 前端把当前输入框中的 Base URL、模型 ID 和非空 API Key 一并作为临时测试配置发送；留空 Key 时复用服务端已保存的 Key。
- 探针只要求模型回复 `OK`，输出上限为 8 tokens，不发送商品档案或参考图。
- 测试不会自动保存配置，避免“测试”产生隐式持久化副作用。

## 交互与状态

配置按钮区加入“测试模型连接”。其下方保留一条常驻状态条，支持：未检测、检测中、模型可调用、鉴权失败、节点不可达、模型调用失败。成功时展示模型名、耗时和简短回复；失败时展示 HTTP 状态与服务端安全错误信息。明文 HTTP 远端在测试前继续弹出风险确认。

## 验证

- 页面结构测试检查按钮、状态条和试调用函数存在。
- JavaScript 语法检查。
- 现有配置探针测试验证成功、鉴权失败与网络状态语义。
- 运行 `seedance_web/tests` 全量回归，并在重启后执行一次真实轻量探针。
