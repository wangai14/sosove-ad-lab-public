# 通用商品提示词工坊 V2 设计

## 目标

在不破坏现有 `/fashion-prompts.html`、AI 配置和历史商品表单的前提下，加入品类专用字段、参考图一致性检查、提示词还原度评分、平台视频预设和本地版本历史。

## 方案比较

1. **渐进增强现有单页（采用）**：保留通用商品档案和三条现有 AI API，在页面内增加动态字段与质量工作台。迁移风险最低，旧链接和旧存储继续可用。
2. **建立第二个“高级模式”页面**：隔离度高，但重复维护商品路由、AI 配置和提示词输出，用户在两个页面间切换成本高。
3. **重写成前端框架应用**：长期扩展性好，但会放大本次改造范围，并破坏当前零构建部署方式。

## 视觉与交互方向

延续现有日系编辑部式工作台：暖白纸张、深墨文字、朱红状态色和高密度信息排版。新增组件不采用通用 SaaS 仪表盘样式，而使用“商品实验记录”语言：品类字段像规格卡，参考一致性像实验预检，评分像检验章，历史像版本档案抽屉。

页面流程固定为：

`通用事实 → 品类专用事实 → 参考图与一致性 → 导演约束 → 平台预设 → AI 生成 → 还原度评分 → 版本保存/比较`

## 数据设计

商品对象新增：

- `categoryDetails`: 当前品类的专用事实键值；服务端限制键数、键长和值长。
- `platformPreset`: `tiktok`、`facebook`、`instagram`、`amazon`、`independent` 或 `custom`。
- `platformStrategy`: 由页面白名单预设生成的节奏、首屏任务、构图安全区和证明重点；服务端重新规范化，不信任任意长文本。

参考一致性报告包含 `status`、`score`、`sameProduct`、`summary`、`conflicts`、`canonicalSources`。一张图直接作为单一权威；两张及以上图片在生成前通过现有视觉模型检查。严重串品阻止生成，轻微视角/光照差异允许继续但写入模型上下文。

提示词还原度由服务端基于最终、已锁定的提示词确定性计算，维度为商品身份、颜色、外形、关键结构、文字边界、部件数量/位置和参考职责。它是“生成前预测分”，不冒充对实际视频画面的视觉验收。

历史版本只保存在浏览器本地，最多 12 个，包含商品档案、提示词、评分、模型记录和参考文件名，不保存图片二进制或 API Key。恢复版本时提示重新绑定参考图；版本比较展示设置差异和每条提示词的文本变化量。

## Seedance 约束

本页保持非叙事商品证明路线：utility intent 是证明当前商品事实；拒绝为商品或操作人编造欲望、冲突或人格。每条提示词只有一个主要生成预算；平台预设只改变节奏、构图和证明顺序，不改变商品事实和参考权威。

参考图仍是一图一主职责。发生冲突时，每个维度只能有一个权威来源；无权威的背面、接口、文字和部件不补全。平台预设是本工作台的创作建议，不声明为任何平台的永久技术上限，最终投放前仍需核对实际广告位规格。

## 失败与恢复

- 一致性检查失败：保留图片和表单，允许重试；不会清空生成历史。
- 检出严重串品：阻止本次生成，要求移除冲突图或调整角色。
- 评分偏低：保留生成结果并给出逐维修复建议，不自动篡改商品事实。
- 本地存储满：淘汰最旧历史；仍失败则关闭历史保存，不影响当前生成。
- 旧存储对象：缺少新字段时使用当前品类默认空字段和 `custom` 预设。

## 验收标准

- 切换品类立即出现对应字段，切回时本轮已填内容仍在。
- 选择平台后自动应用比例和时长，并显示节奏、首屏和安全区说明。
- 多参考图生成前有一致性报告；严重冲突不会调用生成接口。
- 每次 AI 生成和二次精修后展示 0—100 还原度及七个维度。
- 成功生成和精修自动形成版本；可比较并恢复，恢复不包含图片文件。
- 旧页面 URL、旧 AI 配置和现有测试全部继续工作。
